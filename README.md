# Flux Core

Flux is a dual-form NFT/FT asset protocol. Every Asset Unit can exist as an ERC-721 NFT or as
10,000 fungible FLUX tokens, and the protocol keeps the total supply fixed at 10,000 Asset Units.

This repository contains the contracts layer only: Solidity sources, Foundry tests, deployment and
interaction scripts.

## Core design

- **Fixed supply, two forms** — 10,000 Asset Units. One Unit is either one NFT or 10,000 FLUX.
- **Genesis CCA** — 5,000 Credits are sold through a continuous, uniform-price auction with a
  per-bidder budget and maximum price; the remaining 5,000 Units bootstrap FLUX/ETH liquidity.
- **One conversion entry point** — `ConversionEngine` is the only contract that can move an Asset
  between Credit, Genesis NFT, NFT and FT states.
- **Lazy state** — `AssetRegistry` stores only Assets that have actually transitioned; untouched
  ids are derived from the initial Credit/FT split.
- **On-chain art** — `DynamicNFT` metadata and 48×48 SVG are generated by the trait renderer
  contracts; no IPFS or external server is required.
- **ERC-6551 accounts** — every Genesis NFT can own a deterministic token-bound account that holds
  reward assets and is swept atomically when the Genesis is burned.
- **Pull-based rewards** — `RewardVault` tracks liabilities per asset and `GenesisVault` distributes
  them pro rata to active Genesis NFTs.
- **Fee engine** — trading and conversion fees are split across liquidity, Genesis rewards, the
  balance vault and the protocol treasury.
- **Pluggable integrations** — VRF providers, Uniswap V2 liquidity, Uniswap V4 migrators and the
  Flux native AMM are adapters behind small interfaces.

## Contracts

| Contract | Responsibility |
|---|---|
| `core/AssetRegistry` | Canonical Asset state, totals and guarded transitions |
| `core/ConversionEngine` | Credit → Genesis NFT/FT, NFT ↔ FT, fee payment |
| `core/CreditManager` | Credit ownership ledger used by the auction and conversion |
| `token/FluxToken` | ERC-20 with Permit, capped supply, role-gated mint/burn |
| `token/DynamicNFT` | ERC-721 carrying asset id, Genesis flag and trait seed |
| `trait/*` | Trait storage, randomness preparation and fully on-chain SVG metadata |
| `account/*` | ERC-6551 registry, token-bound account and burn settlement |
| `genesis/GenesisAuction` | Continuous CCA auction, credit claims and LP bootstrap |
| `genesis/CCAAllocator` | Pure clearing-price and pro-rata allocation library |
| `economic/FeeEngine` | Fee split and distribution to vaults/strategies |
| `economic/BalanceEngine`, `FeeCurve` | Dynamic fee/reward curve around the target FT/NFT range |
| `economic/RewardAssetRegistry`, `RewardVault`, `GenesisVault` | Multi-asset reward accounting and claims |
| `economic/RewardStrategyManager`, `strategy/HoldETHStrategy` | Pluggable reward strategy execution |
| `vault/LiquidityVault`, `BalanceVault`, `ProtocolVault` | Liquidity compounding, reward budget and treasury |
| `integration/*` | Chainlink VRF, Uniswap V2/V4 adapters, mock migrators and the Flux AMM |
| `interfaces/*` | Shared interfaces and Uniswap V2 type definitions |

See [docs/modules.md](./docs/modules.md) for per-contract details and permissions.

## Getting started

Prerequisites:

- [Foundry](https://book.getfoundry.sh/getting-started/installation) **v1.8.5** (the version CI pins)
- `solc 0.8.26` (pinned in `foundry.toml`)
- Python 3.10+ only for Slither and the coverage script
- Node.js 20+ only if you use the npm script aliases

```bash
git clone git@github.com:lukema95/flux-core.git
cd flux-core
git submodule update --init lib/forge-std lib/openzeppelin-contracts

forge build
forge test                     # 85 tests
bash scripts/check-coverage.sh # line coverage >= 98%
```

Only the two top-level submodules are required. Do not clone recursively into OpenZeppelin unless
you need its test submodules; the contracts only depend on `lib/forge-std` and
`lib/openzeppelin-contracts`.

## Testing and coverage

The suite covers unit, integration, fuzz round-trip and invariant tests:

- 85 tests, 100% passing
- line coverage **98.82%** across `src/` (threshold enforced at 98%)
- invariants: Asset Units are conserved, FLUX supply matches FT units, Genesis rights cannot be
  re-created by NFT/FT round-trips

```bash
forge test -vv
forge coverage --report summary --ir-minimum
COVERAGE_THRESHOLD=98 bash scripts/check-coverage.sh
```

Coverage is measured only on `src/`, excluding tests and scripts. `--ir-minimum` is used to avoid
"stack too deep" errors on the largest renderer contracts.

## Deployment

Copy the environment template and fill in a funded deployer key and RPC URL:

```bash
cp .env.example .env
source .env

./script/flux-forge.sh script script/Deploy.s.sol:Deploy --network local --broadcast
./script/flux-forge.sh script script/Deploy.s.sol:Deploy --network monad --broadcast
```

Deployment addresses are written to `deployments/<chainId>.json` (override the directory with
`DEPLOYMENTS_DIR`). The script wires roles, deploys the full system and can hand admin rights to a
multisig through `PROTOCOL_ADMIN` / `PROTOCOL_TREASURY`.

The full guide — deployment order, verification, post-deployment checklist and network aliases —
is [docs/deployment.md](./docs/deployment.md).

## Security

- No third-party audit has been performed.
- Genesis trait randomness is pseudo-random by design and can be influenced by block producers. Use
  a VRF provider if trait rarity ever carries economic value.
- The protocol has no upgrade proxy; a bug requires migration. Pause authority and admin roles
  should be held by a multisig/timelock.
- Do not open a public issue for a vulnerability; follow [SECURITY.md](./SECURITY.md).
